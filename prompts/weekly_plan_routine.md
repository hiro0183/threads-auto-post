## 手順

### 1. 実測を出す

`python weekly_report.py` を実行する（repo内 `sync/` の累積データから集計するだけ。AI不使用）。
生成された最新の `reports/weekly/{年-W週}.md` を読む。

**「## 0. 経営指標」を最初に読む。** 到達率・エンゲージ率・フォロワー純増の3つがこのアカウントの成績表。

- **到達率が100%未満なら、フックやテーマの話をする前に directives の先頭へ「配管の異常」として書く。**
  投稿が出ていない週の数字は良し悪しの判断材料にならない
- **⚠️ エンゲージ率は2026-09-04に定義が変わった。** それ以前の数値は自分のツリー返信を含んでいて**比較できない**。
  実質ERは全期間0.07%・直近0.24%でほぼ横ばい。**旧ERを根拠にした判断（実験台帳W35-02・W35-03のbaseline 6.9%を含む）は使わない**

### 2. リサーチを回して読む（②リサーチ部門・2026-09-05新設）

`python research_digest.py` を実行し、`prompts/research_digest.md` を読む（AIを呼ばない・数秒）。

1. **今週の題材候補** — 小川さんの脳みそ180題材からの輪番。毎週同じ題材に戻らないための引き出し
2. **読者の声** — `collect_replies.py` が集めた読者の返信
3. **直近14日で使ったテーマ** — 重複回避の材料
4. **本文の骨格の偏り** — どの型に寄っているか

**題材はそのまま使わない。必ず読者の場面へ翻訳する**（読者＝月商100万円以上・自費中心・売上は伸びているが
時間がない治療院経営者）。マーケティング用語のまま投稿にしない。翻訳できない題材は飛ばしてよい。

### 3. ルールを読む

`CLAUDE.md` / `prompts/persona.md`（ペルソナ実数・これ以外の実績数字は禁止）/
`prompts/hook_rules.md`（フック生成ルール・最優先原則0の下限表。必読）/
`prompts/taboo.md`（禁じ手8つ）/ `prompts/funnel_rules.md`（4層ポートフォリオとCTA。必読）。
前週の重複回避のため `posts/weekly_plan/` の最新ファイルも読む。

### 4. 対象の月曜日付を求める

`TZ=Asia/Tokyo date -d '+1 day' +%Y-%m-%d`（このルーティンは日曜に動くので翌日＝月曜が対象週の初日）。

### 5. 週次プランを生成して保存

出力先: `posts/weekly_plan/{月曜日付}.json`

```json
{"week": "{月曜日付}", "directives": [...],
 "days": {"{日付}": [{"slot":"06:00","hook":"...","type":"...","theme":"...",
                     "conclusion":"...","cta":false,"layer":"拡散"}, ...]}}
```

- **7日分。1日のスロットは `post_runner.py` の `SLOT_PLAN` に完全に合わせる**
  （2026-08-27に10→24枠へ拡張済み。**SLOT_PLANが唯一の正**で、`POST_SCHEDULE` はそこから機械的に導出される）
- `hook` は10〜25字（最大35字）。層ごとの狙い・型は `funnel_rules.md`
- **フックの型の下限・上限は `hook_rules.md` 最優先原則0が正**（枠数に対する比率で持つ）
- `cta:true` は SLOT_PLAN で `cta:true` のスロットだけ。文言は `funnel_rules.md` を土台に新作する
- **禁じ手厳守:** 過去投稿の全文リミックス禁止／架空数字禁止／単体禁止／「実は」書き出し禁止／直近7日の同一フック禁止／**テーマ・題材は14日あける**

### 6. フックを機械検査する（2026-09-05に手順化）

`python check_hooks.py posts/weekly_plan/{月曜日付}.json` を実行し、**終了コードが0になるまでフックを直す。**

`hook_rules.md` に下限表が書いてあっても、数えなければ守られない（2026-08の実績は金額入りフックが
1日0.5本、views最下位の「〜な院は」構文が2.4本と、ルールと真逆になっていた）。
**日次執筆者はフックを直せない**ので、ここを通さずにpushすると1週間ぶんが崩れたまま出る。

### 7. directives（改善指示）を書く

週次レポートの「0.経営指標」「2.フックの型別成績」「3.テーマ別成績」を見て、短く書く。

- **a) 到達率:** 100%未満の日があれば筆頭（中身の改善より優先）
- **b) 本文の骨格の偏り:** `research_digest.md` の第4節を見て、40%を超えた日が続いていれば
  「本文の骨格を散らす」と書く（実測で8/12〜22はセリフ型70〜80%、8/26〜29は番号列挙60〜80%と週単位で固着していた）
- **c) 読者の反応:** いいね・読者返信がゼロ続きなら、**題材を変える前に「絡み（人間が他アカウントに反応しに行く仕事）」が要る**と書く。
  投稿の改善だけでは動かない可能性が高い段階（63,660viewsのバズが出た日のフォロワー増が+1人）
- **d) 型の飽き:** 同じ型の連発を輪番で崩す

判定は**毎週**行うが、**ルールブック本体は改定しない**（比率の微調整まで。方針転換は月次スキーム見直しの領域）。

### 8. 実験台帳を更新する（⑤分析部門・PDCAの本体）

`python ledger.py --update` を実行し、`experiments/ledger.json` を読む。

- **judge_on を過ぎているのに verdict が空のカードがあれば、directives の先頭に
  「【要判定】{id} {仮説} — なりあいさんの判断待ち」と書く**（あなたは verdict を書かない。閉じるのは人間の仕事）
- **`baseline_invalid: true` が付いたカードは、baseline が旧エンゲージ率で無効。**
  directives に「【要再設定】{id} baselineを引き直す」と書く
- 開いているカードが3枚未満で、今週あなたが新しい施策を入れるならカードを1枚追加する
  （id は `W{ISO週番号}-0N`、opened は対象の月曜日付、metric は
  `engagement_rate` / `views_median` / `reach_rate` / `followers_delta`、judge_on は4週間後）
- **開いているカードが3枚あるときは新しいカードを作らない**（上限3枚は厳守）
- directives に「今週の観察対象: {開いているカードのid一覧}」を必ず1行入れる

### 9. push

```
git add posts/weekly_plan/ experiments/ prompts/research_digest.md state/
git commit -m "..."
git push origin master
```

**⚠️ pushの絶対ルール:** 必ず `origin master` へ直接push。**別ブランチへのpush・PR作成は禁止。**
push後に `git ls-remote origin master` で自分のコミットが先端にあることを確認し、無ければやり直す。

`prompts/research_digest.md` と `state/theme_shelf_offered.json` も一緒に上げること。
**題材の輪番はこのstateで覚えている**ので、上げ忘れると毎週同じ題材が出る。

## 禁止事項

- IGストーリープラン（`ig_stories/plan/`）はこのルーティンでは作らない（別ルーティンの担当）
- `CLAUDE.md`・`prompts/`・スクリプトの変更（`research_digest.md` の自動生成を除く）
- **`post_runner.py` の SLOT_PLAN / POST_SCHEDULE の変更**（時刻設計はスキーム見直しの領域。触ると投稿が止まる）
- **実験台帳の verdict を書くこと**（判定は人間の仕事。あなたは開くのと実測を埋めるまで）
- `reports/` は .gitignore 済なのでcommitしない
- ペルソナ実数以外の数字の使用、過去の伸びた投稿全文の読み込み
- Anthropic APIを直接使う経路（サブスク完結・API課金ゼロが絶対原則）
