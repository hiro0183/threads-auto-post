# IGストーリー 週次プランのルール（コンサル垢）

> 出典: Obsidian `コンサルThreads/_設計図_Instagram運用_2026-07-08.md` §2〜3。
> **2026-08-24にリポジトリへ移設。** 理由: ルールがObsidianにしか無いとクラウドルーティンから読めず、
> 週次プランの生成がこのPCの起動に依存し続けるため（8/17週・8/24週と2度、プラン未作成が発生した）。
> 設計図の改定時はこのファイルも必ず更新すること。

## コンセプト

黒バック（固定背景）に**読ませるためだけの長文**。1枚目のフックは強い型で思いきり読み込ませ、
**CTAは置かず価値訴求に振り切る**。導線は**プロフィール文で受ける**。

## 出力フォーマット

`ig_stories/plan/{月曜日付}.json`

```json
{
  "week": "2026-08-24",
  "note": "（週テーマと企画メモ）",
  "days": {
    "2026-08-24": {"type": "text", "hook": "（強フック）", "body": "（本文全文）"},
    "2026-08-27": {"type": "photo", "photo_note": "施術風景の写真を1枚", "caption": "（添えるひとこと）"}
  }
}
```

月曜から日曜までの7日分。`render_story.py` がこのJSONから1080x1920のPNGを生成する。

## 各日の要件

| 項目 | 規定 |
|:--|:--|
| hook | **10〜25文字**。常識破壊／断言／数字型のいずれか |
| body | **200〜350文字**（スマホで7〜15秒で読み切れる量） |
| 構成 | **下の「本文の型」に従う（2026-08-24改定）** |
| CTA | **置かない**（例外は週1回まで軽い導線を混ぜてよい） |
| 語り口 | 丁寧語・一人称「僕」・患者を指す語は必ず「**患者様**」 |
| 数字 | **実績・金額・割合は `prompts/persona.md` のペルソナ実数のみ**。手順の番号や「3日」「1ヶ月」などの期間は実績ではないので使ってよい |

## 本文の型（2026-08-24 なりあいさん指示で改定）

> **狙い: 「その場でできる手順」で価値を渡し切り、そのうえで「ここから先は人によって変わる」を示して、
> 相談したくなる余白を残す。売り込まずに引きを作る。**

改定前は「気づき・エピソードで終わる」型だった。読み物としては良いが、
**持ち帰れるものが無く、相談にもつながらなかった**。以下の4ブロックで書く。

### ① 前置き（1〜2行）

読者がその場面を自分ごとにするための一行。問題の言い換えでよい。
例:「施術中に鳴った電話は、記録に残りません」

### ② 手順（番号つき・3〜4個）★ここが本体

**今日か今週、その場で実行できる粒度**にする。

```
1. 電話が鳴って出られなかった時刻をメモする
2. その時間帯だけを紙に書き出す
3. いちばん多い時間に受け口を1つ足す
```

- **道具が要らない／10分〜1週間で終わる**ことだけ書く
- 抽象的な指示（「見直しましょう」「意識しましょう」）はNG。**動詞で終わる具体的な動作**にする
- 各手順は1行。長くなるなら手順を分ける

### ③ 自分の実例（1〜3行）

②を自分がやった結果を、ペルソナ実数を1つ添えて短く。自慢にしない。
例:「僕は週に3日休んでいますが、月商300万を10年間切っていません」

### ④ 「ここから先は人によって変わる」（2〜4行）★引きを作る場所

**手順で渡し切ったうえで、個別性がある一点を名指しする。**
これが「この人に聞いてみたい」を生む唯一の仕掛け。

```
ここまでは誰でもできます
ただ、どの受け口が合うかは
患者様の年齢層で変わります
電話が安心な方もいらっしゃいます
```

- **「ご相談ください」「僕に聞いてください」とは書かない**（CTAなしは維持）
- **失敗の入口を1つ具体的に示す**と効く（「近隣の休診日とぶつけると逆効果です」）
- ここを一般論で締めると引きが消える。**何が人によって変わるのかを必ず名指しする**

## 週テーマの統一（2026-07-30追加）

- 7日分は最初に**ひとつ週テーマ**を決め、その世界観から題材を選ぶ（例: 値上げ／リピート設計／時間術／予約の導線）
- ただし**各日は独立完結**させる。前日の続き・回収のような連続ドラマ化はしない（1本だけ読んでも意味が通ること）
- 型・具体エピソードは7日間で重複させない
- **直近3週のプラン（`ig_stories/plan/` の最新3ファイル）を必ず読み、週テーマとフックを重複させない**

## 書き出しの禁止リスト（Threads側と統一・2026-07-23）

- **1枚目のフックを疑問形で終わらせない**（「〜ですか」「〜ますか」等）。断言型・数字型・失敗談型で書く
- **「実は〇〇」書き出し禁止**（本文中も避ける）
- 体言止めの解説見出しはNG

## 写真日（type=photo）

- 週1〜2日まで。**写真ストックが乏しい週は全日 text でよい**
- 撮り溜めフォルダ: `OneDrive\IGストーリー投稿\写真ストック\`
- 写真日もその週のテーマに寄せる（無理に合わせられない場合はテーマ外でもよい）

## Threads側との重複チェック（2026-07-23の教訓）

**同じ数字・同じエピソードが同じ日に2媒体で出るのは手抜きに見える。**
`posts/weekly_plan/{同じ月曜日付}.json` を読み、その週のThreadsのフック・テーマと
題材が丸かぶりしていないか確認する。かぶっていたら差し替える。

## 自己点検（保存前に必ず実行）

各日について次を確認する。1つでも外れていたら書き直す。

1. hookが10〜25文字か
2. bodyが200〜350文字か
3. hookが疑問形で終わっていないか
4. 「実は」を使っていないか
5. 「患者さん」「患者」になっていないか（必ず「患者様」）
6. **実績・金額・割合**に persona.md 以外の数字が入っていないか（手順の番号・期間は可）
7. **番号つきの手順が3〜4個あるか**（②）
8. **手順がすべて具体的な動作か**（「見直す」「意識する」等の抽象指示が混ざっていないか）
9. **「ここから先は人によって変わる」で、何が変わるのかを名指ししているか**（④が一般論で終わっていないか）
10. **「ご相談ください」等のCTAを書いていないか**
11. 7日間で型・題材が重複していないか
12. 直近3週の週テーマと重複していないか
13. 同じ週のThreadsと題材がかぶっていないか
